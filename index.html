What this does, what gets sent, and what it never does

What the AI does. One model call per request: Claude (claude-haiku-4-5, by Anthropic) reads your text, runs up to five real web searches, and proposes sources across five blindspot categories. Server-side code then drops every suggestion that is not backed by an actual search result URL — if the model cannot ground a suggestion in a search it ran, you never see it. The page tells you how many were dropped. Every run is live and unique — nothing is cached or replayed.

What gets sent. The text you paste is sent to Anthropic's API to be read by the model, and the model's search queries go out to the web. Nothing is stored by this site; there is no database and no analytics on the text.

What it never does. It does not judge whether your story is good. It does not contact anyone. It does not replace your editor: every suggestion is a lead to verify with your own reporting before you rely on it, and it never suggests private individuals — only organizations, officials, public records, and expert roles.

How this fits newsroom AI standards. Hearst's published AI-use principles (the Houston Chronicle's parent) permit generative AI to support reporting and research by organizing and surfacing material "which is then evaluated by reporters and editors," under editorial oversight and with clear disclosure. This tool is built to live inside that box: AI is not a journalist here — it surfaces leads, the page labels everything the model touched, and a journalist evaluates every item before it goes anywhere near a story.

The sample drafts were written for this demo. Their facts draw on real Houston Chronicle reporting, credited and linked on each sample; no Chronicle text is reproduced.

Full disclosure: this demo was itself built with AI. Claude wrote the code and this page overnight, directed and reviewed by Trevor Brown. The source suggestions are model output, labeled as such — and the gate that checks their grounding is plain, tested code.
